# 표로롱 — 네이버 카페·블로그 표 변환

한글 for Mac에서 복사한 표와 본문을 네이버 카페·블로그 에디터에 붙여넣을 수 있도록 HTML을 변환하는 macOS 메뉴바 앱입니다. 문서 전체에 여러 표가 있어도 원래 순서대로 처리합니다.

공식 저장소는 [largeq/nanoome-pyororong](https://github.com/largeq/nanoome-pyororong)이며, [피드백 및 지원 요청](https://github.com/largeq/nanoome-pyororong/issues/new?template=feedback.yml)은 GitHub 문의 양식에서 받습니다.

앱의 정식 이름은 **표로롱**이며, 기능을 소개할 때만 **표로롱 — 네이버 카페·블로그 표 변환**으로 표기합니다. 앱 파일은 `표로롱.app`, Bundle ID는 `com.phronesis.pyororong`, 실행 파일·앱 모듈·빌드 스킴·Swift 패키지 이름은 `Pyororong`입니다. 버전은 화면에서 **2.0**, 앱 메타데이터에서 `2.0.0`으로 관리하며 빌드 번호는 별도입니다.

새 Bundle ID로 처음 실행할 때 기존 `com.phronesis.tableconverter`의 단축키·사용법 표시 설정과 안내 완료 여부를 한 번 가져옵니다. 새 앱에 이미 저장한 설정은 덮어쓰지 않으며 이전 설정도 삭제하지 않습니다. 이전 버전에서 변환해 둔 클립보드는 다시 쓰지 않고 완료 상태로 인식합니다. 이후 변환 결과에는 `com.phronesis.pyororong.converted-table` 표식을 사용합니다.

GitHub 배포를 위한 지원 범위, 완료 기준, 진행 상태는 [배포 준비 계획](docs/release-plan.md)에 기록합니다. 원본 글꼴 보존 등 계획의 목표는 아래에 설명한 현재 앱의 동작과 구분합니다.

## 설치

**2.0.0(빌드 1)**의 [첫 GitHub Release](https://github.com/largeq/nanoome-pyororong/releases/tag/v2.0.0)를 게시했습니다. 배포용 Universal 앱의 Developer ID 서명, Apple 공증과 티켓 스테이플, Gatekeeper 검증을 마쳤고, 기존 공개 DMG·체크섬과 운영 업데이트 안내 파일도 확인했습니다. 당시 결과는 [배포 검증 기록](docs/validation/release-2.0.0/README.md), 설치창을 정리한 r2 포장의 확인 범위는 [설치창 변경 기록](docs/validation/dmg-layout-2026-10-29/README.md)에 구분해 기록합니다.

macOS 12 이상, Apple Silicon·Intel Mac용입니다. [DMG 설치 파일](https://github.com/largeq/nanoome-pyororong/releases/download/v2.0.0/Pyororong-2.0.0-1-r2.dmg)을 내려받아 열고, 흰 바탕의 설치창에서 왼쪽 `표로롱.app`을 오른쪽 **응용 프로그램** 폴더로 끌어다 놓은 뒤 복사된 앱을 실행합니다. 복사가 끝나면 디스크 이미지는 추출해도 됩니다. 설치창을 정리한 r2 포장 파일이며 앱 버전은 **2.0.0(빌드 1)** 그대로입니다.

Python이나 Xcode는 필요하지 않습니다. 주요 기능과 사용 시 참고 사항은 [2.0 릴리스 안내](docs/releases/2.0.0.md)에 있습니다.

## 실행

1. `표로롱.app`을 실행합니다.
2. 한글에서 **표 하나 또는 표가 들어 있는 문서 전체**를 선택해 `⌘C`로 복사합니다.
3. **⌘⌥⇧P**(Command + Option + Shift + P)를 누르거나, 메뉴바의 표 아이콘에서 **표 변환하기**를 선택합니다.
4. 완료 알림을 확인하고 네이버 카페 편집 화면에 `⌘V`로 붙여넣습니다.
5. 메뉴바의 **표로롱 종료**로 앱을 종료합니다.

처음 실행하면 복사 → 변환 → 붙여넣기의 세 단계와 무음 시연이 있는 사용법 창을 바로 표시합니다. 안내는 한 화면에 모여 있으며 **시작하기**로 닫습니다. 단계를 선택하면 해당 단계에서 일시정지하며, 창을 다시 활성화해도 재생되지 않습니다. 현재 등록된 변환 단축키를 표시하며, 단축키가 꺼져 있으면 메뉴로 변환하는 방법을 안내합니다.

최초 안내를 **시작하기**로 완료하거나 닫기·Esc·⌘W로 건너뛰면 다음 실행부터 자동으로 표시하지 않습니다. **앱을 시작할 때마다 이 안내 표시**는 기본 해제이며, 체크하면 매번 표시합니다. 체크 상태는 변경 즉시 저장합니다. 기존 사용자가 저장한 표시·숨김 선택은 업데이트 후에도 유지됩니다. 메뉴의 **사용법 보기**로 언제든 같은 화면을 다시 열어 설정을 바꿀 수 있습니다. 창 하단에서도 안내하듯이, 안내 창을 닫아도 메뉴바 앱은 계속 실행됩니다. 창이 닫히거나 비활성화되면 재생을 멈추며, **동작 줄이기** 설정이 켜져 있으면 재생 대신 단계 선택으로 확인합니다.

Tab·Shift-Tab으로 단계·표시 설정·시작하기 버튼을 탐색하고, Space로 선택한 버튼을 누릅니다. Return은 **시작하기**, Esc·⌘W는 창 닫기입니다. 창을 열 때 버튼에 자동으로 포커스를 주지 않으며, Tab 탐색 시에는 시스템 포커스 링을 유지합니다. 현재 단계는 테두리로 구별하고 VoiceOver에는 단계와 재생 상태를 제공합니다. 자동 시연은 반복 음성 알림을 요청하지 않습니다.

**표로롱에 관하여**에서는 정식 명칭 **표로롱**, 버전, 제작 배경과 목적, 제작자 정보를 확인할 수 있습니다. **프로젝트 페이지**는 GitHub 저장소를 열며, **오픈 소스 라이선스**에서 앱에 포함된 고지를 읽을 수 있습니다.

메뉴바의 **피드백 및 지원**에서 **이메일로 문의…**와 **GitHub에 의견 남기기…**를 선택할 수 있습니다. 이메일은 기본 메일 앱에서 수신 주소·제목·문의 본문과 실제 앱·macOS 버전이 입력된 초안을 엽니다. 사용자가 내용을 편집하고 직접 보내야 전송됩니다.

GitHub는 문제 신고·개선 제안·사용 문의를 하나의 양식에서 받고, 실제 앱·macOS 버전을 미리 입력합니다. GitHub 로그인 후 사용자가 직접 작성·제출하며 답변과 처리 상황은 같은 글에서 확인합니다. 내용과 첨부파일은 공개되므로 개인정보를 포함하지 마세요. 어느 문의 방식에서도 클립보드·문서·로그를 자동으로 첨부하거나 문의를 자동 전송하지 않습니다.

메일 앱이나 브라우저를 열지 못하면 해당 문의 주소 복사와 **닫기**를 제공합니다. 사용자가 복사를 선택하기 전에는 클립보드를 바꾸지 않습니다. 이메일 수신 주소는 `App/Info.plist`의 `PyororongSupportEmail`에 설정하며, 주소가 없으면 이메일 관련 항목을 삭제하지 않고 비활성화합니다. GitHub 문의는 계속 사용할 수 있습니다.

GitHub 문의 양식과 빈 이슈 접수를 제한하는 설정을 공개 저장소의 `main` 브랜치에 게시했고 Issues 기능이 활성화된 것을 확인했습니다. 누구나 저장소를 볼 수 있으며 GitHub 로그인 후 문의를 작성할 수 있습니다. 실제 양식에서 문의 종류와 앱·macOS 버전 자동 입력을 확인했습니다. 앱에서는 로그인 정보나 GitHub 토큰을 저장하지 않습니다.

앱을 켜 둔 동안에는 한글·Chrome·Safari 등 다른 앱을 사용 중에도 단축키로 변환할 수 있습니다. 먼저 `⌘C`로 복사해야 하며, 단축키는 복사한 내용을 변환합니다. 이미 변환한 내용에 다시 누르면 클립보드를 바꾸지 않고 붙여넣기 준비 상태를 안내합니다.

메뉴바의 **설정…**을 열고, **표 변환하기** 옆의 단축키 칸을 클릭한 뒤 **원하는 키 조합을 직접 누르고 저장**합니다. Command·Control·Option·Shift 중 두 개 이상을 누른 채 영문자가 적힌 키 하나를 누르며, Command 또는 Control을 포함해야 합니다. 예를 들어 Command + Shift를 누른 채 P를 누릅니다. 입력 중에는 설명을 숨기고, 잘못된 입력에서만 키 이름과 입력 방법을 안내합니다. 다른 앱과 충돌하면 해당 오류만 표시하고 기존 설정을 유지합니다.

입력 중에는 기존 변환 단축키가 잠시 해제되므로 현재 사용 중인 조합도 그대로 입력할 수 있습니다. **Esc**는 입력을 취소하고 **Tab**은 다음 조작으로 이동합니다. **취소**, 창 닫기 또는 **⌘W**는 저장하지 않고 닫습니다. 변경 내용이 있고 입력·오류 상태가 아닐 때 **저장**할 수 있습니다. **단축키 사용**을 끄면 **표 변환하기**와 입력칸을 함께 회색으로 표시하지만 메뉴에서 변환하는 기능은 유지됩니다. **기본 단축키로 복원**(⌥⇧⌘P)은 키 조합만 되돌리며 사용 여부는 바꾸지 않습니다.

**저장**한 설정은 앱을 다시 실행해도 유지됩니다. 다른 프로그램이 단축키를 선점해 등록할 수 없으면 안내하며, 변경에 실패한 경우 이전 단축키를 유지합니다. 한글 입력 상태에서도 같은 물리 글쇠로 동작합니다. 단축키 등록과 설정 창의 직접 입력을 위해 손쉬운 사용·입력 모니터링 권한을 추가로 요청하지 않습니다.

메뉴의 **업데이트 확인…**은 **표로롱에 관하여** 바로 위에 있으며, 자동 확인 여부와 관계없이 새 버전을 직접 확인합니다. **설정…** 창의 업데이트 영역에서 **자동으로 업데이트 확인**을 선택할 수 있습니다. 기본은 켬이며 앱 실행 중 하루 간격으로 확인합니다. 변경은 **저장**을 눌러 적용하고, **취소**·창 닫기는 저장하지 않습니다. 사용자가 저장한 선택은 재실행 후에도 유지합니다.

자동 확인으로 새 버전을 발견하면 메뉴에 **업데이트 확인… (새 버전 있음)**을 표시합니다. 메뉴를 누르면 버전과 변경 사항을 확인하고 설치를 선택할 수 있습니다. 자동 다운로드·자동 설치는 제공하지 않으며, 사용자가 설치를 선택한 경우에만 진행합니다. 업데이트를 위한 재실행은 표 변환이 끝날 때까지 미룹니다. 실제 배포에는 서명·공증된 앱과 공개된 업데이트 안내 파일이 필요하며, 공개 파일이 없거나 연결이 실패하면 확인 실패로 안내합니다. 배포 준비와 현재 연결 상태는 [업데이트 배포 안내](docs/updates.md)를 참고하세요.

변환 결과는 알림 권한과 관계없이 메뉴바 아래의 작은 결과창에 표시합니다. 작업하던 앱과 입력 위치를 유지하며, 소리나 별도의 확인 버튼은 없습니다. 안내는 **변환 완료**, **변환 완료(확인 필요)**, **변환하지 못했습니다**, **이전 변환 결과**의 네 가지 기본형을 사용합니다. 완료 안내는 **네이버 카페·블로그에서 붙여넣기(⌘V)하세요.**로 통일합니다. 그림·형광펜·대각선의 조합과 관계없이 확인 필요 안내는 같은 요약을 사용하며, 발견된 항목과 실제 그림 수만 **자세히 보기**에 표시합니다.

정상 완료는 초록 체크와 함께 약 3.5초, 확인 필요는 노란 체크와 함께 약 8초 동안 표시합니다. 마우스를 올리거나 상세를 펼쳐 읽는 동안에는 자동으로 닫히지 않습니다. 실패는 직접 닫을 때까지 유지하고, 원인에 따라 **사용법 보기** 또는 **다시 변환**을 제공합니다. 읽지 못한 색상 값과 예상하지 못한 오류의 원문은 상세에 보존합니다. 현재 클립보드와 다른 결과가 표시되면 회색 시계와 이전 결과 안내로 구분하고, 붙여넣기 지시와 복구 버튼을 표시하지 않습니다. 창 밖 클릭이나 오른쪽 위 닫기 버튼으로 닫을 수 있습니다.

그림·형광펜·대각선의 제한은 실제 발생한 항목만 자세히 보기에 표시합니다. 현재 복사 내용의 닫힌 완료 안내는 메뉴의 **변환 결과 보기**, 오류 안내는 **오류 안내 보기**에서 다시 확인합니다. 새 내용을 복사하면 이전 결과창을 닫고, 메뉴는 새 복사 내용에 맞춰 바뀝니다. macOS 26 이상에서는 시스템 Liquid Glass를 사용하며, 이전 버전에서는 흐림 효과로 표시합니다. **투명도 줄이기** 설정에는 불투명 배경으로, **동작 줄이기** 설정에는 펼치기·접기 애니메이션 없이 대응합니다.

붙여넣기 단축키 **⌘V**는 본문에서 안내하며 창 아래에 중복 표시하지 않습니다. 그림 추가 안내에는 강제 줄바꿈을 넣지 않고 창 너비에 맞춰 표시합니다. 시스템 유리 테두리는 유지하면서 본문 뒤에 밝은·어두운 모드별 중립 배경을 두어, 뒤쪽 화면의 색이 글자 영역에 지나치게 비치는 것을 줄였습니다.

표는 원래 열 너비의 비율을 유지하며 카페 에디터의 본문 너비에 맞춥니다. 필요하면 붙여넣은 뒤 전체 너비를 조정할 수 있습니다.

메뉴를 열면 맨 위에 현재 상태를 안내하고, 바로 아래 시스템 구분선으로 실행 명령과 나눕니다. 표가 없으면 **표 변환하기**를 비활성화하고, 변환 중에는 **변환 중…**, 완료 후에는 **변환 결과 보기**, 실패 후에는 **오류 안내 보기**로 바뀝니다. 복사한 내용을 확인하는 동안과 변환 준비가 끝났을 때는 상단 문구를 **변환할 표가 있습니다**로 통일합니다. 확인하는 동안에는 이전 명령을 비활성화하고, 확인 결과 변환할 표가 없으면 **한글에서 표를 복사하세요**로 바뀝니다. 변환·결과 / 설정 / 사용법·지원·업데이트·앱 정보 / 종료를 구분선으로 묶습니다. **⌘,**는 앱의 창이 활성화되어 있을 때 설정을 엽니다. 등록된 전역 변환 단축키는 표가 없거나 복사한 내용을 확인 중이어서 **표 변환하기**가 비활성화되어도 유지하고, 변환 중에도 표시합니다. **변환 결과 보기**·**오류 안내 보기**에는 변환 단축키를 표시하지 않습니다. 단축키를 사용 해제했거나 등록하지 못한 경우에는 표시하지 않습니다.

상단 상태 안내는 macOS 14 이상에서 선택할 수 없는 시스템 메뉴 섹션 헤더를 사용합니다. 메뉴의 제목·활성 여부·단축키는 값이 실제로 바뀔 때만 갱신해, 메뉴를 열어둔 동안 같은 항목을 반복해서 비활성화했다가 활성화하지 않습니다. 좌우 클릭 모두 AppKit의 기본 상태 버튼과 메뉴를 사용합니다. macOS 27에서는 버튼의 클릭 동작을 직접 받아 메뉴를 표시하는 동안에만 연결하고, 닫히면 연결과 버튼의 선택·눌림 상태를 함께 해제합니다. 이전 macOS에서는 기존 시스템 메뉴 연결을 유지합니다. 메뉴 요청·열기·닫기는 내용이나 클립보드를 포함하지 않는 `StatusMenu` 시스템 로그로 남깁니다.

메뉴바의 표 아이콘은 클립보드 상태를 표시합니다.

- **표만 표시**: 변환할 한글 표가 없는 기본 상태입니다.
- **오른쪽 아래 꽉 찬 원**: 변환 가능한 한글 표가 복사되어 있습니다. **표 변환하기**를 누르세요.
- **내부 선이 움직이는 표**: 변환 중입니다. 바깥 테두리는 고정되고 가로선 두 개와 세로선 한 개가 시간차를 두고 그려졌다 지워집니다. 한 주기는 2초이고 초당 60회 갱신하도록 설정하며, 변환 중에는 중복 실행을 막습니다.
- 변환이 끝나면 현재 보이는 선에서 약 0.16초 동안 표를 마저 채운 뒤 체크 표시로 넘어갑니다. 그리거나 지우는 중이어도 다음 주기까지 기다리지 않습니다. 이 짧은 마무리 동안에도 실제 변환 결과는 이미 붙여넣을 수 있습니다.
- **오른쪽 아래 굵은 체크 표시**: 변환된 표가 클립보드에 저장되어 네이버 카페에 붙여넣을 수 있습니다. 원 없이 체크만 표시하며, 완료 시 체크가 약 0.42초 동안 한 번 그려진 뒤 그대로 남습니다.
- **오른쪽 아래 느낌표**: 변환에 실패했습니다. 오류 안내를 확인한 뒤 다시 시도하세요. 다른 내용을 복사하거나 변환에 성공하면 해제됩니다.

완료 표시는 다른 내용을 복사할 때까지 유지됩니다. 다른 내용을 복사하면 상태를 다시 판단하며, 앱을 다시 실행해도 클립보드에 남은 변환 결과를 알아봅니다.

아이콘은 배지를 제외한 표 본체가 가운데에 오도록 정렬합니다. 표 높이는 13.6pt로, 기준 ChatGPT 아이콘 높이의 80%이며 표와 배지의 비율을 유지합니다. 가로 캔버스와 메뉴바 항목 너비는 24pt로, 그림 크기를 유지하면서 좌우의 불필요한 투명 여백을 줄입니다. 체크와 느낌표는 표의 우측 하단에 겹치며, 주변을 투명하게 비워 표의 선과 구분합니다.

변환 계산은 백그라운드에서 실행해 메뉴바의 움직임과 조작을 유지합니다. 변환 도중 새 내용을 복사하면 덮어쓰지 않고 안내합니다. macOS 손쉬운 사용의 **동작 줄이기**가 켜져 있으면 움직임 없이 각 상태를 표시합니다.

앱 실행에는 Python이나 Xcode가 필요하지 않습니다. 앱의 변환 기능은 로컬에서 실행되며 표 내용을 서버로 전송하지 않습니다.

## 앱 아이콘

`Assets/AppIcons/Pyororong.icon`을 정식 앱 아이콘으로 사용합니다. 표와 프네 로고를 별도 레이어로 유지하며, 기본 외관에서는 검은 표, 다크 외관에서는 흰 표를 표시합니다. 프네 로고의 색과 위치·크기는 두 외관에서 같습니다.

[Apple의 Icon Composer 연동 방식](https://developer.apple.com/documentation/xcode/creating-your-app-icon-using-icon-composer)에 따라 Xcode에서 레이어를 컴파일하고, 구형 macOS용 `.icns`도 생성합니다. Finder·Dock의 아이콘 외관은 [macOS의 아이콘 및 위젯 스타일 설정](https://support.apple.com/guide/mac-help/mchlp1225/mac)을 따릅니다. 시스템 외관에 맞춰 전환하려면 다크 스타일의 자동 옵션을 사용합니다. 구형 macOS에서는 기본 아이콘을 사용합니다.

앱 정보창은 `Assets/Images.xcassets/AboutAppIcon.imageset`에 보관한 라이트·다크 PNG를 창의 외관에 맞춰 자동 전환합니다. `scripts/export-about-icons.sh`는 기본 `.icon`과 `Assets/IconComposerSVG 2`의 6~10단계 `.icon`을 Apple의 `ictool`로 렌더링해 이 이미지와 `AboutEasterEgg6`~`AboutEasterEgg10` 이미지를 갱신합니다. `scripts/build-app.sh`에서 자동 실행하며, Xcode에서 직접 빌드할 때는 원본을 수정한 뒤 이 스크립트를 먼저 실행합니다. 메뉴바의 단색 표 및 변환 상태 애니메이션은 기존 템플릿 아이콘을 사용합니다.

정보창의 아이콘 뒤에는 밝은 모드에서 아래로 드리우는 은은한 그림자, 다크 모드에서 푸른 청록빛 후광을 표시하며 외관 변경에 맞춰 자동 전환합니다. 누르는 동안 작아지고 놓으면 원래 크기로 돌아옵니다. 1~5회는 기본 아이콘을 유지하고, 6~10회는 각 단계 이미지로 바뀝니다. 10회에는 이름도 초록·청록·파랑 그라데이션의 **프네프네 포로롱**으로 바뀌고, 흰빛이 약 1.1초 동안 왼쪽에서 오른쪽으로 한 번 지나갑니다. 그라데이션은 5초 동안 유지된 뒤 기본 아이콘과 이름으로 복원됩니다. **동작 줄이기**가 켜져 있으면 반짝임 없이 그라데이션을 표시합니다. 창을 닫거나 다시 열면 횟수와 타이머를 초기화합니다.

## 개발 환경과 빌드

- Swift 버전의 최소 대상: **macOS 12 Monterey**
- 검증한 개발 도구: **Xcode 27.1 / Swift 6.4**
- 의존성: **SwiftSoup 2.14.3** — Swift Package Manager로 관리
- Release 앱은 Apple Silicon(`arm64`)과 Intel(`x86_64`) 코드를 함께 포함합니다.

기존 Python 안내의 macOS 10.15 요구사항은 Swift 버전에 적용되지 않습니다. 현재 Xcode SDK와 선택한 SwiftSoup 릴리스의 지원 범위에 맞춰 최소 대상을 macOS 12로 설정했습니다. 구형 macOS와 Intel 하드웨어에서의 실제 실행 검증은 별도로 필요합니다.

Xcode에서 `Pyororong.xcodeproj`를 열고 `Pyororong` scheme과 `My Mac` 실행 대상을 선택하면 개발할 수 있습니다.

터미널에서는 프로젝트 루트에서 실행합니다.

```sh
bash scripts/build-app.sh
```

생성되는 앱:

```text
.build/xcode/Build/Products/Release/표로롱.app
```

`표로롱.command`와 `표로롱 (백그라운드).command`도 위 앱을 실행합니다. 앱이 없으면 먼저 빌드하므로, 이 실행 방식에는 Xcode가 필요합니다. 소스를 수정한 후에는 다시 빌드해야 합니다.

`scripts/build-app.sh`는 **로컬 개발 빌드**를 만듭니다. 서명은 Xcode 설정에 따라 개발용 또는 ad-hoc이며, 이 빌드에서는 hardened runtime을 끕니다. GitHub 배포용은 별도로 Developer ID 서명·Apple 공증을 거친 앱을 사용하고, `scripts/prepare-update.sh`로 DMG와 업데이트 안내 파일을 준비합니다. 자세한 절차는 [업데이트 배포 안내](docs/updates.md)에 있습니다.

## 코드 구조

- `App/`: 앱 생명주기, 메뉴바, 변환 결과 알림
- `Sources/TableConverterCore/`: 한글 HTML 분석과 네이버용 HTML 생성
- `Sources/TableConverterMac/`: macOS 클립보드 읽기·쓰기, 전역 단축키 등록과 설정 저장
- `Tests/`: Python 결과와의 비교, 변환 경계 사례, 별도 테스트용 클립보드 검증
- `Package.swift`, `Package.resolved`: 라이브러리와 고정된 의존성 버전

메뉴바와 설정 창은 AppKit으로 구현했습니다. 변환 모듈과 클립보드 모듈은 UI에서 분리되어 있습니다.

두 번째 명령은 Apple Silicon·Intel Release 앱을 빌드한 뒤 실제 AppKit 코드로 결과 안내·지원과 앱 정보·설정·메뉴·업데이트·사용법의 통합 검사 6개를 실행합니다. 메뉴 검사는 별도 클립보드와 임시 설정을 사용해 좌우 클릭·접근성 활성화·메뉴 연결 해제·중복 열기 방지와 빈 상태·변환 가능·변환 중·완료·실패, 새 복사 내용 보호, 결과 열기 시 클립보드 보존을 확인합니다. 지원 검사는 외부 URL 열기를 대체해 이메일·GitHub 문의 초안과 열기 실패 복구를 확인하며 실제 문의를 보내지 않습니다. 설정의 저장·취소·단축키 충돌 복구·자동 업데이트 확인 선택과 앱 정보의 외관·아이콘 효과도 검사합니다. 업데이트 검사는 로컬 시험 서버로 최신·새 버전·미지원·프리뷰·연결 및 XML 오류를 구분하고 자동 설치 금지와 변환 중 재실행 연기를 확인합니다.

사용법 창은 840pt 너비와 내용에 맞춘 높이, 세 단계의 즉시 표시, 번들 영상의 재생·반복과 0·5·9초 단계 선택, 5초 뒤로·재생/일시정지·5초 앞으로 조작, 마우스·키보드 포커스에 따른 컨트롤 표시, 영상 누락 안내를 검사합니다. Tab·Shift-Tab·Return·Esc·⌘W, 단계 선택에 따른 일시정지·창 활성 전환, 동작 줄이기 대응, 표시 설정 저장과 최초 안내 완료도 확인합니다. 밝은·어두운·고대비 외관 및 긴 문구의 글자 잘림·버튼 최소 폭·시스템 버튼 높이를 검사하고 실행별 `.build/diagnostics/app-<날짜와 시각>/`에 화면을 저장합니다. 임시 설정을 사용하며 일반 클립보드와 시스템 손쉬운 사용 설정은 변경하지 않습니다. VoiceOver 실제 음성 읽기와 구형 macOS 실행은 별도 확인이 필요합니다.

사용법 창은 [Apple 버튼 지침](https://developer.apple.com/design/human-interface-guidelines/buttons)의 표준 macOS push button과 [WWDC20의 콘텐츠 크기 기반 배치 지침](https://developer.apple.com/videos/play/wwdc2020/10219/)을 따릅니다. **시작하기** 버튼은 오른쪽에 정렬하고 AppKit의 기본 높이를 사용합니다. 최소 폭 **70pt는 이 프로젝트의 선택**이며 더 긴 문구는 시스템 콘텐츠 크기에 맞춰 확장합니다. 사용법 창은 840pt 너비를 유지하고 높이는 내용에 맞춥니다. 본문과 하단 영역의 간격은 16pt이며, **시작하기** 버튼은 하단 안내문과 아래쪽을 맞춥니다. 긴 문구에 더 큰 공간이 필요한 경우에는 창 높이를 확장합니다. 최초 안내 정책은 [온보딩 지침](https://developer.apple.com/design/human-interface-guidelines/onboarding), 동작 줄이기 대응은 [모션 지침](https://developer.apple.com/design/human-interface-guidelines/motion)을 근거로 합니다.

`Tests/TableConverterCoreTests/Fixtures/python-reference.json`은 별도로 보존한 Python 코드에서 얻은 결과입니다. 원본 코드의 SHA-256과 한글 클립보드 예시 5개의 셀 병합, 셀 스타일, 문단, 글자 서식, 일반 텍스트를 기록했습니다. 비교 시 무작위 UUID는 제외합니다. 테스트 실행에는 Python이 필요하지 않습니다.

클립보드 테스트는 고유한 이름의 테스트용 클립보드를 사용하며 사용자의 일반 클립보드를 바꾸지 않습니다. 자동 검사는 실제 한글·브라우저·네이버 카페 사이의 붙여넣기 검증과 구분합니다. 실제 붙여넣기는 사용자가 완료했다고 확인했습니다.

2026년 10월 24일에는 변환 검사 30개와 테스트 전용 클립보드 검사 9개, 총 39개가 통과했습니다. 실제 문서의 표 구조와 서식은 유지하고 본문·링크·그림 주소를 익명화한 회귀 검사 자료도 포함합니다. 두 아키텍처의 Release 빌드와 로컬 서명 검증이 통과했습니다.

2026년 10월 25일에는 단축키 관련 검사 6개를 추가해 **총 45개**가 통과했습니다. 실제 macOS 단축키 이벤트 전달, 누르고 있기의 반복 방지, 충돌 시 이전 조합 유지, 등록 해제와 설정 저장을 검사했습니다. 별도 시험 클립보드·임시 설정으로 실제 앱 코드의 변환, 중복 실행 방지, 작업 창 유지, 설정 창의 기본값·해제·복원을 확인했습니다. 이 검사는 사용자의 일반 클립보드와 단축키 설정을 변경하지 않았습니다.

이후 단축키를 직접 눌러 지정하는 방식으로 보완하며 **총 48개** 검사가 통과했습니다. 앱 통합 검사에서 직접 입력·입력 중 변환 방지·Esc 취소·저장·취소·충돌·해제·기본값 복원을 확인했습니다. 설정 창은 내용에 맞춰 크기가 조절되며, 저장 버튼 아래 여백은 오류 안내 유무와 관계없이 20포인트로 유지됩니다.

녹색·분홍색 형광펜 누락을 보완하며 **총 65개** 검사가 통과했습니다. HTML에 없는 형광펜도 같은 클립보드의 한글 전용 데이터에서 읽어 복원합니다. 실제 표의 녹색 6구간·분홍색 1구간과 Chrome 카페 편집기의 색상·글자 위치를 보조 붙여넣기 시험으로 확인했습니다. 문서 전체의 바깥 표 10개·530개 셀도 글자·병합·셀 서식이 유지됐습니다. 원본과 글자 위치를 대조할 수 없거나 전용 데이터를 읽지 못하면 기존 HTML을 변환하고 형광펜 확인이 필요함을 안내합니다.

제공받은 문서 전체를 앱의 실제 클립보드 모듈로 변환하고 Chrome의 새 카페 글쓰기 탭에 실제 붙여넣기했습니다. 바깥 표 10개가 모두 생성됐고, 중첩 표는 첫 표의 행으로 펼쳐졌습니다. 전체 글자와 각 칸의 병합을 확인했으며, 첫 두 표는 Windows 기준 게시글과 글자·행·셀·병합 값이 일치했습니다. 본문과 두 표의 순서는 별도의 보조 붙여넣기 시험으로 확인했습니다. 글 등록·임시저장은 하지 않았습니다. 자세한 결과와 남은 검증은 [배포 준비 계획](docs/release-plan.md)에 기록합니다.

변환 중·완료 아이콘 애니메이션을 추가하며 **총 70개** 검사가 통과했습니다. 비동기 변환의 형광펜 보존·변환 도중 새 복사 내용 보호·취소 시 원본 유지와 아이콘의 동일한 칸 높이·체크 영역만 바뀌는 동작을 검사했습니다. 별도 시험 클립보드로 실제 앱 코드의 변환 중 연속 프레임, 완료 체크의 한 번 재생과 고정, 중복 실행 방지, 실패 시 기본 상태 복귀, 작업 창 유지도 확인했습니다. 두 아키텍처의 Release 빌드와 로컬 서명 검증이 통과했습니다.

완료 전환 순서를 보완한 뒤 **총 76개** 검사가 통과했습니다. 실제 앱 코드의 빠른 변환은 약 0.8초에 표 그리기를 마친 뒤 원 없는 체크로 넘어갔습니다. 지우는 도중 완료되는 경우에는 다음 표가 완성된 상태에서 전환되는 것을 확인했습니다. 표시 대기 중 새 내용을 복사하면 이전 결과의 완료 표시를 생략하며, 일반 클립보드를 변경하지 않는 별도 시험 클립보드로 검증했습니다.

결과 안내창을 Figma 시안에 맞춰 적용한 뒤 **총 81개** 자동 검사가 통과했습니다. 별도 AppKit 시험 창으로 밝은·어두운 모드의 성공·일부 확인·실패 안내와 상세 항목, 펼치기·접기 높이 복원, 글자 잘림 없음, Liquid Glass 적용을 확인했습니다. 마우스를 올린 동안 자동 닫힘 중지·이탈 후 재개, 상세 내용을 읽는 동안 유지, 실패 안내 유지·재시도, 새 복사 시 이전 안내 닫기와 최근 결과 구분도 통과했습니다. 기존 완료 아이콘 순서 통합 검사도 통과했으며, 이 검사들은 일반 클립보드와 작업 중인 앱을 변경하지 않았습니다. 구형 macOS의 흐림 효과와 손쉬운 사용 설정을 직접 전환한 외관 검증은 별도로 필요합니다.

Ponytail 리뷰의 확인 사항을 수정한 뒤 패키지 검사 **89개**와 실제 안내창 검사 **1개**가 통과했습니다. 상태 확인 중 메인 스레드 응답, 검사 결과의 변환 재사용, 검사 도중 새 복사 내용 보호, 나중에 추가된 HWP 형식의 형광펜 복원, 개행과 함께 있는 NBSP 보존을 확인했습니다. 이전 결과창은 같은 클립보드를 반복 확인해도 유지되고, 새 내용을 복사하면 닫힙니다. 사용법 시연과 메뉴바는 같은 아이콘 그리기를 사용합니다. 두 아키텍처의 Release 빌드도 통과했습니다.

2026년 10월 28일 저장소 이름과 소스를 동기화하며 패키지 검사 **96개**(변환 코어 47개·Mac 모듈 49개)가 통과했습니다. 결과 안내·지원·단축키 설정·메뉴·사용법의 AppKit 통합 검사 5개와 Apple Silicon·Intel Release 빌드, 로컬 서명 검증도 통과했습니다. 문의와 프로젝트 페이지는 새 저장소 주소를 직접 사용하며, 기존 사용자 설정과 클립보드를 읽는 호환성 식별자는 유지합니다.

2026년 10월 29일 최종 소스와 정식 에셋으로 패키지 검사 **98개**(코어 47개·Mac 모듈 51개), 업데이트를 포함한 AppKit 통합 검사 **6개**, Apple Silicon·Intel Universal Release 빌드와 로컬 ad-hoc 서명 검증을 통과했습니다. 앱 아이콘·정보창·사용법 영상·통합 설정·Sparkle 업데이트 확인·지원 메뉴와 60Hz 갱신 및 약 0.16초 마무리를 확인했습니다. 실제 실행 로그·대표 화면·미확인 범위는 [이번 최종 검사 기록](docs/validation/2026-10-29/README.md)에 있습니다. 실제 한글·네이버 붙여넣기, 다른 Mac·구형 macOS 실행과 서명·공증된 앱의 운영 업데이트 교체는 이번에 확인하지 않았습니다.

이후 첫 정식 배포에서는 사용자가 실제 한글·네이버 붙여넣기를 완료한 것으로 확인했고, 2.0.0(빌드 1) 배포 앱의 Universal 구조·Developer ID 서명·hardened runtime·공증 티켓·Gatekeeper 검증을 통과했습니다. 공개 설치 파일과 체크섬의 원본 일치, 운영 업데이트 안내 파일의 HTTP 200 응답과 실제 Sparkle의 최신 버전 판정도 확인했습니다. 다른 Mac·구형 macOS 실행, VoiceOver 음성 읽기와 지속 60fps 실측은 사용자 선택으로 이번 배포 검증에서 제외했습니다. 첫 배포에는 이전 공증 버전이 없으므로 실제 업데이트 교체는 다음 업데이트 때 확인합니다.

## 현재 변환 범위

- 본문과 모든 바깥 표를 문서 순서대로 변환합니다. 표가 없는 일반 문서만의 변환은 지원하지 않습니다.
- 표 안의 표는 바깥 표의 행으로 펼치고 주변 셀의 병합을 조정합니다. 지나치게 복잡한 구조는 원본 클립보드를 유지하며 실패를 안내합니다.
- 가로·세로 셀 병합, 셀 배경색, 글자색, 글자 형광펜, 굵게, 밑줄, 취소선, 기울임, 문단과 명시적인 줄바꿈, 좌·중·우 정렬을 처리합니다.
- 글자 배경색 외에 한글 전용 HWP 5 데이터의 형광펜 영역도 읽습니다. 문서 전체 글자의 순서가 일치할 때 색을 적용해 반복 문구에 잘못 칠하지 않도록 합니다.
- 대각선은 제외하고 알림으로 안내합니다.
- 원본 셀 너비를 비율로 계산해 적용합니다. 셀 병합이 있는 표에도 서로 다른 열 너비를 전달합니다.
- 원본 글꼴·글자 크기·줄 간격을 전달합니다. 글자 자체뿐 아니라 상위 요소와 문서 스타일시트에서 물려받는 서식도 읽습니다.
- 원본에 지정된 테두리와 여백을 전달하고, 테두리 정보가 없으면 검은색 1px 실선을 사용합니다.
- 웹 링크와 웹 주소가 있는 그림은 전달합니다. 한글의 로컬 그림과 데이터 형식 그림은 자동 전송하지 못하며, 변환 완료 시 별도로 추가해야 할 그림 수를 안내합니다.

실제 표시에는 네이버 편집기의 제한이 적용됩니다. 이번 Chrome 시험에서는 나눔바른고딕과 원본 10pt의 13px 표시를 확인했지만, 작은 글자는 최소 11px로 조정됐고 굴림은 네이버 기본 글꼴로 대체됐습니다. 양쪽 정렬은 왼쪽 정렬로 표시됐습니다. 그림, 여백, 줄 간격 등까지 포함한 원본 또는 Windows 결과와의 완전한 일치는 확인하지 않았습니다. Safari·블로그와 게시 후 표시는 추가 검증이 필요합니다.

문자열로 HTML을 재구성할 때 특수문자가 태그로 해석되지 않도록 이스케이프하며, 실패하거나 변환 중 클립보드가 바뀌면 원본을 덮어쓰지 않습니다. 일반 글자와 중첩된 서식을 함께 순회하므로 서식 없는 글자가 빠지거나 중첩된 글자가 중복되지 않도록 처리합니다.

## 기존 Python 버전

기존 Python 구현은 별도로 보관합니다. 해당 구현의 실행·패키징 스크립트는 Python 버전용이며, 이 저장소에는 현재 Swift 앱을 개발하고 실행하는 파일을 포함합니다.

현재 폴더의 `.command`는 `scripts/run-app.sh`를 통해 이 폴더의 Swift 앱을 실행하며, 앱이 없으면 `scripts/build-app.sh`로 빌드합니다. 프로젝트를 옮길 때에는 기존 위치의 Swift 빌드 캐시를 `.build/previous-location/`에 보존하고 새 캐시로 검사했습니다. 이후 산출물 정리 내역은 [배포 준비 계획](docs/release-plan.md)에 기록합니다.

SwiftSoup의 라이선스는 `THIRD_PARTY_NOTICES.txt`에 포함되어 있습니다.
