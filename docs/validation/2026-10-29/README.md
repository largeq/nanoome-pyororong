# 2026년 10월 29일 최종 소스 검사

검사 환경은 Apple Silicon(`arm64`), macOS 27.0(`26A428`), Xcode 27.1(`27A9275`), Swift 6.4다. 날짜와 시각은 한국 시간 기준이다. 과거 성공 기록을 대신 사용하지 않고 이번 작업의 소스와 정식 에셋으로 실행했다.

## 검토 범위와 보존

- 시작 브랜치: `codex/app-icon-appearances`, 기준 커밋: `99e685b`.
- 원격: `https://github.com/largeq/nanoome-pyororong.git`. 시작 당시 원격 `main`도 같은 커밋이었다.
- 기존 변경 파일 21개와 삭제 파일 1개, 새 코드·검사·에셋·문서·스크립트 전체를 검토했다. 초기화·덮어쓰기·강제 push는 사용하지 않는다.
- 저장소와 상위 경로에서 `AGENTS.md` 파일은 발견되지 않았다. 대화에서 전달된 착수 전 수정 금지 지침과 이번 명시적 착수 요청을 적용했다.
- 표시 이름 `표로롱`, 프로젝트·앱 모듈·실행 파일 `Pyororong`, Bundle ID `com.phronesis.pyororong`, 최소 대상 macOS 12.0을 확인했다.

새 `UpdateController`는 앱 시작·메뉴·설정과 연결되고 Sparkle 2.10.1을 정확한 버전으로 고정한다. 새 `UsageGuideVideoView`는 기존 시연 코드 대신 사용되며 삭제한 `UsageGuideIllustration`의 빌드·검사 참조도 교체되어 있다. 정식 `.icon`, 이미지 카탈로그, 영상, 제삼자 고지는 Xcode 리소스에 연결되어 있다. `Assets/IconComposerSVG 2`의 6~10단계 `.icon`은 아이콘 출력 스크립트가 사용하므로 함께 저장한다.

SwiftSoup 2.14.3과 Sparkle 2.10.1의 라이선스 전문을 고지와 대조했다. 정식 영상은 `Assets/UsageGuide/usage-guide.mp4`이며 H.264, 1280×800, 30fps, 약 12.933초다. 1초 간격 샘플을 육안 확인했다. 텍스트 소스·에셋에서 개인 키, 일반적인 GitHub/AWS 인증 정보 패턴과 개인 컴퓨터 절대 경로를 검사해 검출되지 않았다. 모든 영상 프레임에 대한 개인정보 전수 검사는 수행하지 않았다.

`output/`의 영상 편집 도구·캐시·썸네일·중간 렌더는 로컬에 보존하고 `.gitignore`로 제외한다. `.build/`, 사용자 설정, 압축 배포물과 인증 정보도 저장하지 않는다. 아래 자료는 이번 검사의 선별된 로그와 화면이며 원본 전체 빌드 산출물은 포함하지 않는다.

## 이번에 보완한 부분

- README의 다음 애니메이션 주기까지 기다린다는 설명을 현재 선을 약 0.16초 마무리하는 동작으로 수정했다. 60Hz 갱신 설정과 영상 조작·검사 설명, 현재 16pt 간격도 반영했다. 날짜가 붙은 과거 검사 이력은 보존했다.
- `scripts/test-app.sh`의 과거 날짜 고정 경로를 실행별 `.build/diagnostics/app-<날짜와 시각>/`으로 바꿨다. 테스트 조건이나 기대 결과는 완화하지 않았다.
- 그 밖의 기존 앱 아이콘·정보창·영상 안내·설정·업데이트·지원 메뉴·애니메이션 변경을 검토하고 보존했다. 추가로 수정해야 할 확정된 앱 코드 결함은 발견하지 못했다.

## 실제 실행 결과

`swift test`는 종료 코드 0으로 **98개 통과, 실패 0, 건너뜀 0**이었다. 변환 코어 47개와 Mac 모듈 51개다. 0.16초 마무리, 그리기·지우기 도중 완료, 취소·새 상태 보호, 메뉴 추적 중 프레임 갱신, 클립보드·설정 보존 회귀 검사를 포함한다. 자세한 실행 결과는 [swift-test.log](swift-test.log)에 있다.

`bash scripts/test-app.sh`는 최종 경로 변경 후 다시 실행해 종료 코드 0으로 **통합 검사 6개 모두 통과**했다. 실행 자료 경로는 `.build/diagnostics/app-20261029-201250/`이다.

1. 결과 안내: 밝은·어두운 외관, 완료·확인 필요·실패, 상세와 복구 버튼, 이전 결과 구분, 재열기, 일반 클립보드 보존.
2. 지원·앱 정보: 이메일과 GitHub 두 메뉴, 초안 인코딩, 주소 누락, 열기 실패 복구, 명시적 복사, 앱 정보 문구·선택·레이아웃, 아이콘 효과와 10회 클릭 동작. 라이선스 전문과 번들 포함 여부는 별도로 대조했다.
3. 설정: 단축키 입력·유효성·충돌 복구·기본값, 저장·취소·해제, 자동 업데이트 확인 선택, 키보드·마우스, 밝은·어두운·고대비 외관.
4. 메뉴: 상태별 명령·구분선·단축키, 좌우 클릭·접근성 활성화·중복 열기 방지·메뉴 연결 해제, 설정·업데이트 연결, 변환 중 보호와 새 복사 내용 보존.
5. 업데이트: 실제 Sparkle과 로컬 시험 서버로 최신·새 버전·미지원·프리뷰·404·잘못된 XML 구분, 설정 보존, 자동 다운로드·설치 금지, 조용한 알림, 변환 중 재실행 연기와 설정 오류 복구. 설치 파일 요청은 발생하지 않았다.
6. 사용법 영상: 번들 파일 로딩과 재생 위치, 반복, 0·5·9초 단계 선택, 5초 이동, 마우스·키보드 컨트롤, 영상 누락 안내, 비활성 창 정지, 동작 줄이기, 최초 안내·표시 설정과 여러 외관의 배치. 재생 실패 안내 분기는 코드로 검토했으며 손상 영상을 통한 실패 유도 검사는 하지 않았다.

검사 요약과 실제 레이아웃 치수는 [app-checks.log](app-checks.log)에 보관했다. 이메일·브라우저 열기는 시험 핸들러로 대체했다. 실제 이메일 발송이나 GitHub 문의 제출은 하지 않았다. 메일 열기 실패 시 이메일 주소 복사와 닫기 안내는 유지된다.

Universal Release 빌드는 성공했다. 앱 실행 파일과 포함된 Sparkle 모두 `x86_64 arm64`이며 두 앱 슬라이스의 최소 OS는 12.0이다. `codesign --verify --deep --strict --verbose=2`는 종료 코드 0으로 앱과 Sparkle 내부 구성요소를 검증했다. 서명 종류는 **로컬 ad-hoc**이고 Developer ID 배포 서명이 아니다. 모든 `scripts/*.sh`의 Bash 문법 검사와 `git diff --check`도 통과했다. 명령과 출력은 [build-verification.txt](build-verification.txt)에 있다.

추가로 `prepare-update.sh`에 이번 로컬 앱을 입력했을 때 Developer ID·hardened runtime 요건으로 종료 코드 1을 반환하고 새 출력 폴더·아카이브를 만들지 않는 것을 확인했다. 이 경로에서는 Keychain 서명 단계에 진입하지 않는다.

최초 제한 환경 실행은 Swift 사용자 캐시 접근과 Icon Composer 파일 접근 제한으로 검사 시작에 실패했다. 필요한 환경 접근을 허용받아 같은 소스로 다시 실행했고 위 결과를 얻었다. 앱 코드나 검사 조건을 바꿔 그 실패를 숨기지 않았다.
