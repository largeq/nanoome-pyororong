# 2026년 10월 29~30일 DMG 가운데 정렬

사용자의 의도는 창 축소가 아니라 원래 창 안에서 위아래 여백을 같게 하는 것이었다. [r3 축소안](../dmg-spacing-2026-10-29/README.md)을 취소하고 **768×480pt**로 복원했다. 안내 문구부터 아이콘 아래 파일명까지를 하나의 묶음으로 잡아 실제 Finder의 흰 본문 영역에서 수직 중앙에 배치했다.

## 실제 화면 측정

[새 Finder 화면](finder.jpg)을 원본 [r2 화면](../dmg-layout-2026-10-29/finder.jpg)과 독립적으로 비교했다. 두 화면은 모두 1536×960px의 2배 캡처이며 제목·탭·상태 막대를 제외한 흰 영역은 y=120~902px다.

- 기존 묶음은 y=432~786px, 위 312px·아래 116px로 아래에 치우쳐 있었다.
- 원래 배치에서 49pt 올린 새 묶음은 y=334~688px다. **위 214px·아래 214px, 차이 0px**로 확인했다.
- 원래 창 크기, 안내와 파일명 표시, 아이콘·글자 크기와 드래그 동작은 유지했다. JPEG 가장자리의 연한 안티앨리어싱까지 잡는 보조 진단은 1px 차이를 별도로 기록했다. 주검사 기준은 원본 분석 때 정한 RGB≤160·행당 3픽셀 이상으로 동일하게 유지했다.

측정 결과는 [centering.json](centering.json), 재현 코드는 [verify-centering.swift](verify-centering.swift), Finder에 저장한 치수·좌표는 [layout.json](layout.json)에 있다. 이미지 자체를 변경해 맞춘 것이 아니다.

## DMG 검증

기존 공증 앱 **2.0.0(빌드 1)**을 그대로 담은 `Pyororong-2.0.0-1-r4.dmg`다. 생성기의 완성본 검증에서 원본 앱과 파일·디렉터리·심볼릭 링크 137개 항목의 바이트·권한 일치를 확인했다. 새 이미지 무결성, 내부 앱 서명·공증 티켓·Gatekeeper·Universal 검사와 앱 내장 공개 키에 대한 DMG 전자서명 검증을 통과했다. 외부 DMG 자체를 별도 Apple 공증한 것은 아니다.

새 DMG와 체크섬의 비로그인 다운로드가 검증본과 일치했다. 운영 feed의 HTTP 200 응답도 커밋과 같았으며 실제 `UpdateController`·Sparkle 조회가 정확한 r4 URL과 최신 2.0.0(빌드 1), 오류 `1001`·이유 `1`을 확인했다. 자동 다운로드·설치는 요청하지 않았다.

조회 후 첫 외부 정리 확인은 12초 안의 연속 4회 안정화 조건을 마치지 못해 실패했다. 이 기록을 보존하고, 운영 조회를 반복하거나 조건을 완화하지 않은 채 같은 조건의 별도 읽기 전용 확인을 수행했다. 4회 모두 시험 호스트·설정·프로세스 잔존 0으로 통과했다. 비어 있는 UUID 시험 plist 한 개만 정리했으며 클립보드와 프로덕션 설정 값·파일은 보존됐다.
