# 2026년 10월 29일 배포·중복 파일 정리

사용자가 Release의 ZIP을 포함한 불필요한 파일 정리를 요청했고, 로컬 임시 산출물도 정리 범위에 포함한다고 확인했다. 앱 버전은 **2.0.0(빌드 1)**로 유지했다.

## 배포 파일 통일

직접 설치와 Sparkle 업데이트가 기존의 같은 DMG를 사용하도록 운영 appcast를 전환했다. 해당 DMG 바이트를 기존 Sparkle 키로 서명하고 실제 앱에 들어 있는 공개 키로 전자서명을 검증했다. 버전·공개 키·내부 앱과 DMG 바이트는 변경하지 않았다.

Sparkle 2.10.1의 실제 `SUDiskImageUnarchiver` 원본을 사용하는 별도 검사에서 DMG를 추출했다. 앱만 추출됐고 응용 프로그램 링크는 설치 대상에서 제외됐다. 원본과 파일·권한·심볼릭 링크 78개 항목이 일치했으며, 깊은 서명 검사·공증 티켓·Gatekeeper 승인·Universal 검사가 통과했다. 앱 설치나 실행 없이 추출 후 마운트 정리까지 확인했다.

운영 주소의 실제 Sparkle 조회에서 최신 **2.0.0(빌드 1)** 판정과 정확한 `.dmg` URL 선택을 확인한 뒤, Release의 `Pyororong-2.0.0-1.zip`과 ZIP 전용 `SHA256SUMS`를 삭제했다. Release에는 기존 DMG와 `.dmg.sha256` 두 파일만 남고, 두 파일의 자산 ID와 해시는 유지됐다. GitHub가 태그별로 자동 생성하는 Source code ZIP/TAR 링크는 업로드한 설치 파일과 구분된다.

## 저장소와 로컬 정리

- `Assets/IconComposerSVG/`: 22개 파일 모두 실제 사용 중인 `Assets/IconComposerSVG 2/`의 대응 파일과 바이트가 같아 삭제했다. `.icon` 원본을 포함한 정식 추적 에셋 36개는 Git 원본과 대조해 보존했다.
- 중복 에셋 ZIP 2개: 압축 내부 항목 각각 18개·22개가 정식 에셋과 일치하고 고유 원본이 없어 삭제했다.
- 사용하지 않는 구형 `table_icon.png`, Finder `.DS_Store` 11개와 구형 로컬 ZIP 생성 스크립트를 삭제했다. 이 단계는 총 **37개 파일, 823,244바이트**다.
- `.build/`의 빌드 캐시·다운로드 의존성·복사본·시험 앱·임시 로그와 `output/`의 중간 영상·편집 산출물을 삭제했다. 삭제 전 `du` 보고 용량은 합계 **4,165,492,736바이트(약 4.17GB)**였다. 공유 블록·스냅샷을 고려한 실제 디스크 여유 공간 증가량을 뜻하지는 않는다.

공증된 원본 앱은 프로젝트 밖에 그대로 보존했다. 정식 아이콘·이미지 카탈로그·메뉴바 에셋·사용법 영상·라이선스·검사 자료·개인 Xcode 설정과 Git 이력도 유지했다. 필요한 검사 결과는 캐시 삭제 전에 이 디렉터리로 옮겼다. 캐시와 내려받은 의존성은 다음 빌드 때 다시 생성되며, `.DS_Store`는 Finder가 폴더를 열 때 다시 만들 수 있다.

`scripts/prepare-update.sh`도 DMG·전용 체크섬·DMG 전자서명을 포함한 appcast와 변경 사항 사본을 만들도록 바꿨다. 최종 스크립트로 실제 패키징·체크섬·서명 검사를 통과했고, 같은 버전을 다시 배포하려는 입력을 출력 생성 전에 거부하는 기존 조건도 유지됐다. 첫 패키징 시험은 시험용 빈 RSS의 Sparkle XML 네임스페이스 누락으로 실패했으며, 유효한 시험 입력으로 수정 후 통과했다.

중복 에셋 삭제 후 첫 보존 확인에는 삭제 대상으로 승인된 `.DS_Store`까지 포함한 오류가 있어 실제 정식 추적 파일 36개를 Git과 다시 대조했다. 캐시 삭제도 Finder 임시 파일 재생성으로 한 차례 중단돼 같은 승인된 경로만 재시도했으며 최종적으로 두 디렉터리를 모두 제거했다. 앱 구현이나 검증 기대값을 바꿔 실패를 숨기지 않았다.
