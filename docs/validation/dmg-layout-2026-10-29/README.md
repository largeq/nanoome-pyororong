# 2026년 10월 29일 DMG 설치 창 적용

사용자가 선택한 흰 배경 시안에서 본문 상단 로고와 큰 제목을 제거했다. 한 줄 안내와 가운데 화살표, 왼쪽 `표로롱.app`과 오른쪽 `응용 프로그램` 링크만 배치했다. 두 아이콘과 파일명은 Finder의 실제 항목이다.

앱은 기존 **2.0.0(빌드 1)** 공증 원본을 그대로 사용한다. 포장 변경을 구분하기 위해 새 파일은 `Pyororong-2.0.0-1-r2.dmg`와 해당 `.sha256`으로 제공한다. 기존 주소에 다른 서명 대상 바이트를 덮어쓰지 않는다.

## 실제 검증

- Finder에서 새 DMG를 직접 열어 안내·화살표·아이콘 배치를 확인했다. [실제 화면](finder.jpg)과 [창 설정](layout.json)을 보존했다. 탭·상태 막대 등 Finder 자체 표시에는 이 Mac의 사용자 설정이 적용된다.
- 읽기 전용 UDZO/APFS 이미지 무결성 검사를 통과했다. 내부 앱은 원본과 137개 항목(파일·심볼릭 링크 78개, 디렉터리 59개)의 바이트·권한·링크가 일치했다.
- 내부 앱의 깊은 서명 검사, 공증 티켓, Gatekeeper의 `Notarized Developer ID` 승인과 Apple Silicon·Intel Universal 검사를 통과했다. 외부 DMG 자체를 Apple에 별도로 공증한 것은 아니다.
- DMG의 Ed25519 전자서명을 원본 앱에 내장된 공개 키로 검증했다. 새 DMG와 체크섬의 비로그인 HTTP 200 다운로드가 로컬 파일과 일치했다.
- 실제 Sparkle 2.10.1 `SUDiskImageUnarchiver`로 앱 하나만 추출되는 것을 확인했다. 숨김 배경·`.DS_Store`와 응용 프로그램 링크는 추출되지 않았으며 추출 앱도 원본과 일치했다. 임시 마운트가 남지 않은 것을 확인했다.
- 최종 `prepare-update.sh`로 유효한 빈 시험 feed에 대한 패키징·서명·체크섬 생성을 실행했다. 새 생성기는 완성 DMG의 내부 서명과 원본 일치까지 확인한다. 기존 운영 feed에 같은 빌드 번호를 다시 넣는 입력은 출력 생성 전에 거부했다.
- 운영 feed의 HTTP 200 응답이 커밋한 r2 안내와 일치했다. 실제 `UpdateController`와 Sparkle의 정보 조회에서도 정확한 r2 URL과 최신 2.0.0(빌드 1) 판정(`1001`, 이유 `1`)을 확인했다. 자동 다운로드·설치 요청은 없었다.

첫 Sparkle 추출 시도는 Finder 확인용으로 같은 이미지가 두 번 마운트되어 있어 `resource busy`로 실패했다. 해당 두 마운트를 정상 추출한 뒤 같은 원본 코드와 조건으로 통과했다. 도구 준비 중 Xcode 인자 이름 오타도 지원되는 `-clonedSourcePackagesDirPath`로 정정했다. 검사 조건을 완화하지 않았다.

운영 조회용 프로세스의 첫 샌드박스 실행은 AppKit 시작 단계에서 지연돼 외부 60초 제한으로 종료됐다. UUID 시험 환경이 생성되지 않은 것을 확인한 뒤, 같은 실행 파일과 검사 조건으로 샌드박스 밖에서 재시도해 통과했다. 프로덕션 설정과 일반 클립보드는 보존됐으며 시험 프로세스·UUID 호스트·설정 파일은 최종적으로 모두 0개였다. 논리적으로 비어 있던 UUID 설정 plist 한 개도 내용 확인 후 정리했다.

앱 구현·버전·Bundle ID·공개 키·사용자 설정은 바꾸지 않았다. 실제 새 버전 설치·교체·재실행과 다른 Mac 실행은 이번 DMG 외관 변경의 검사 범위에 포함하지 않았다.
